# Release v0.1.2

[![GitHub Downloads](https://img.shields.io/github/downloads/alexdelprete/ha-harmony-ng/v0.1.2/total?style=for-the-badge)](https://github.com/alexdelprete/ha-harmony-ng/releases/tag/v0.1.2)

**Release Date:** 2026-11-07

**Type:** Patch release - Activity and command buttons, remotes named after their product, fixes
found testing the API and MQTT transports on a live Hub.

## What's Changed

### Added

- One button per activity on the Hub, named "Start" and the activity, which starts it.
- One button per command on each configured device. These are disabled by default, since a device
  knows dozens of commands; enable the ones you use. A press sends one tap of the command.

Both follow the Hub's configuration without a reload.

### Changed

- Remote devices are named and modelled after the product the Hub reports, for example
  "Harmony Ultimate". The slot number is added only when two remotes share a product. The device
  updates in place when the product becomes known; entity ids, and names you set yourself, stay
  as they are.
- Firmware that does not report the product names every touchscreen remote `elite`, which was
  wrong for Ultimate, 950 and other remotes. That guess is no longer shown: such a remote is a
  "Harmony remote" without a model until the firmware reports the product. Companion and Smart
  Control remotes keep their names.
- README: the MQTT transport is documented, and the event example uses the remote's current
  entity id.

### Fixed

- Bluetooth hosts: the address was read from a key the Hub does not send, so all hosts shared an
  empty address and only one connectivity sensor was created. Each host now gets its own sensor,
  and the leftover sensor with the empty address is removed.
- Remote battery, voltage and charging show unknown until the remote's first report, instead of
  the Hub's 0 % placeholder.
- MQTT transport: device and activity types were read from the message type field.
- The link to the Hub's web UI is shown on the MQTT transport too.
- The firmware release check gets up to two minutes to answer, on both transports. The Hub
  retries its downloads, so a check on a slow network outlasted the 10 second request limit.
- The client library is tested against payloads recorded from the firmware.

## Firmware notes

Some of these features need harmony-ng changes that are not in an upstream release yet:

- The remote's product name needs firmware that reads the remote's skin id.
- Live battery readings need the fix that delivers the remote's status to the Hub's event bus.
- Over MQTT, the firmware update entity and Help need the update and Help actions on the Hub's
  command channel.

On older firmware these parts keep their previous behaviour; nothing breaks.
