# Release v0.1.4

[![GitHub Downloads](https://img.shields.io/github/downloads/alexdelprete/ha-harmony-ng/v0.1.4/total?style=for-the-badge)](https://github.com/alexdelprete/ha-harmony-ng/releases/tag/v0.1.4)

**Release Date:** 2026-11-08

**Type:** Patch release - the infrared receiver keeps capturing after a Hub restart.

## What's Changed

### Fixed

- Infrared receiver: the Hub starts every boot with capture off, and the receiver turned it on
  only when the entity was added. After a Hub restart it stayed silent until Home Assistant
  restarted. Capture is now turned on again whenever the Hub comes back, and whenever the Hub
  reports it off: in a new status, in its `ir_capture` WebSocket event, or in the republished
  MQTT `hub` object. Turning capture off from the Hub's web UI, REST or MQTT while the receiver
  is enabled turns it back on within a moment.

### Changed

- The client library is tested against the firmware's recorded infrared capture: a real
  `ir_received` event, the `ir_capture` event, the capture toggle's reply and the raw infrared
  request that sends the timings back.

## Upgrade notes

- **Firmware:** following capture changes as they happen needs the harmony-ng change that reports
  the capture state in the snapshot, the MQTT `hub` object and the `ir_capture` event. It is not
  in an upstream release yet. On older firmware the receiver still turns capture on again when the
  Hub reconnects after a restart; nothing breaks.
