# Release v0.1.0

[![GitHub Downloads](https://img.shields.io/github/downloads/alexdelprete/ha-harmony-ng/v0.1.0/total?style=for-the-badge)](https://github.com/alexdelprete/ha-harmony-ng/releases/tag/v0.1.0)

**Release Date:** 2026-11-06

**Type:** Minor release - First release of the Harmony NG integration.

Home Assistant integration for a Logitech Harmony Hub running the open-source
[harmony-ng](https://github.com/iranl/harmony-ng) firmware. The Hub pushes every change over a
WebSocket, so activities, remotes and Bluetooth hosts update in Home Assistant the moment they
change, without polling.

## Requirements

- Home Assistant 2026.11.0 or newer.
- A Harmony Hub running harmony-ng with the event bus (`api_version` 2 or newer). Older harmony-ng
  releases and stock Logitech firmware are not supported.

## What's Changed

### Added

- Config flow with mDNS discovery of `_harmony-ng._tcp`, manual setup by address, reauthentication
  and reconfiguration. Optional Personal Access Token when the Hub has authentication enabled.
- Two transports: REST and WebSocket (default) with push updates from the Hub's event bus, and
  MQTT through Home Assistant's MQTT integration.
- `remote` entity per Hub with the attributes and services of the core Harmony integration
  (`remote.turn_on` with an activity, `remote.turn_off`, `remote.send_command` with device, repeats,
  delay and hold), so existing automations port with a change of entity id. One more `remote` per
  configured IR or Bluetooth device, as a child device of the Hub.
- Activity select, activity state, firmware, last-boot and busy sensors, and a firmware `update`
  entity that checks the Hub's release once a day and installs it from Home Assistant.
- Per paired RF remote (Elite, Ultimate, Companion, Smart Control): battery, voltage, charging and
  configuration-sync sensors, wake and sleep buttons, an `event` entity for every key press.
- Bluetooth hosts paired with the Hub as connectivity sensors.
- Infrared emitters for the front blaster and the two emitter jacks, usable by Home Assistant's
  infrared integrations (LG, Samsung, Marantz, Dyson and others) as their transmitter. An infrared
  receiver entity, disabled by default, for firmware that supports capture.
- Services `harmony_ng.ir_send`, `harmony_ng.bt_key`, `harmony_ng.activity_help`,
  `harmony_ng.activity_help_answer`, `harmony_ng.activity_cancel` and `harmony_ng.sync`.
- Device triggers, diagnostics, repair issues for an offline Hub and for discovery, debug logging
  from the entry menu, English translations.
- Vendored `pyharmonyng` client library for the Hub's REST and WebSocket API.
- Harmony NG brand images served by the integration.
- Home Assistant quality scale `platinum`: every Bronze to Platinum rule done or exempt.

## Notes

- Firmware support for the integration's API (event bus, mDNS announcement, raw infrared) was
  developed together with this release; see the
  [architecture document](https://github.com/alexdelprete/ha-harmony-ng/blob/v0.1.0/docs/HA_INTEGRATION_ARCHITECTURE.md)
  and the [firmware specification](https://github.com/alexdelprete/ha-harmony-ng/blob/v0.1.0/docs/HA_INTEGRATION_FIRMWARE_SPEC.md).
- Infrared capture is not yet implemented in the firmware, so the receiver entity stays unavailable
  until it is.
